  ### Pourquoi MetaMask affiche des frais en AVAX ?

  1. La devise native dépend du réseau actif dans MetaMask :
      • Sur Ethereum et Sepolia, la devise native est l'ETH (ou SepoliaETH).
      • Sur Avalanche (Mainnet ou testnet Fuji), la devise native est l'AVAX.
      MetaMask affiche exclusivement le symbole de la cryptomonnaie du réseau qui est actuellement sélectionné dans votre
      extension.
  2. Désynchronisation entre le frontend et le wallet :
      • Votre frontend lit les données via le RPC Sepolia configuré dans Wagmi.
      • Mais au moment d'écrire une transaction (useVotingTx.ts), Wagmi transmet l'ordre à window.ethereum (MetaMask).
      • Si votre MetaMask est resté positionné sur le réseau Avalanche Fuji Testnet (dont l'URL Infura figurait d'ailleurs
      dans votre .env.example), MetaMask prépare la transaction pour le réseau Avalanche. Il calcule donc les frais en
      AVAX et s'apprête à envoyer la transaction sur la mauvaise blockchain (où votre contrat n'existe pas !).

          await publicClient.simulateContract({ ...request, account: address } as never);
          const hash = await mutateAsync(request as never);
          const receipt = await publicClient.waitForTransactionReceipt({ hash });
          
          if (receipt.status !== "success") throw new Error("La transaction a échoué (revert).");
          setState({ status: "success", message: successMessage });
          await queryClient.invalidateQueries({ queryKey: ["voting"] });
          return true;
        } catch (error) {
          setState({ status: "error", message: formatError(error) });
          return false;
        }
      }
    
      return { send, state, isPending: state.status === "pending", reset: () => setState({ status: "idle" }) };
    }

  ──────
  ### 1. Le défi technique côté Smart Contract

  Dans ~/develop/alyra/voting/src/Voting.sol, une fois l'étape VotesTallied atteinte :

  1. Aucun statut suivant n'existe : le contrat est bloqué dans cet état final.
  2. Chaque électeur inscrit a hasVoted = true.
  3. Pour recommencer en gardant les inscrits, il faut obligatoirement pouvoir :
      • Remettre le statut à RegisteringVoters (pour éventuellement ajouter d'autres électeurs) ou directement à
      ProposalsRegistrationStarted.
      • Vider la liste des propositions (proposalsArray).
      • Permettre aux électeurs de revoter.


  │ Caution
  │ Le piège du DoS par boucle :
  │ Pour remettre hasVoted = false à tous les électeurs, une mauvaise pratique consisterait à faire une boucle for sur
  tous
  │ les électeurs. Comme votre contrat a précisément été optimisé pour éliminer les boucles (anti-DoS sur tallyVotes), une
  │ boucle ici recréerait une faille de dépassement de gas !

  #### La solution optimale en O(1) de Gas : Le Session ID (ou Round)

  Plutôt qu'un booléen hasVoted, on suit le numéro de session pendant lequel l'électeur a voté :

  • Le contrat a un compteur uint256 public currentSession = 1;.
  • Un électeur est considéré comme ayant voté dans la session en cours si voter.votedSession == currentSession.
  • Pour réinitialiser le vote : l'admin appelle resetVotingSession() qui fait simplement currentSession++, vide
  proposalsArray et remet winningProposalID = 0.
  • Résultat : Coût en gas infime (~35 000 gas), pas de boucle, aucun risque de blocage, et tous les électeurs restent
  inscrits (isRegistered = true) tout en pouvant immédiatement revoter !
